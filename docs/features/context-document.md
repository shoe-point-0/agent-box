# Versioned agent context and output schemas

Status: implemented.

The `internal/contextdoc` package projects an immutable `contract.Plan` and a
complete set of live READY observations into the versioned `context.json`
document consumed by agents and tools. It verifies generation, Box identity,
Plan digest, repository facts, and service readiness before writing atomically
at mode `0600`, and enforces an explicit allowlist plus secret-canary scanning
so credentials, host paths, private Git stores, and Docker sockets cannot leak
into context output.

The Draft 2020-12 context schema stays strict while supporting additive
evolution: Milestone 1 boxes emit empty route and port arrays, and later
milestones populate live loopback endpoints in the same validated structure.
Runtime adapters and daemon wiring call into `internal/contextdoc` from
[`abox up`](abox-up.md); SQLite cache rows are never treated
as live-resource authority.

## Scope and dependencies

- Milestone 1 core contract. Depends on [schema contracts](schema-contracts.md), [atomic file writer](atomic-file-writer.md), and [SQLite state store](sqlite-state-store.md). Source: `THE_BEGINNING.md` Sections 14.2 and 14.4.

## Behavior

- Projects an immutable Plan and one complete live observation set into `contract.Context`, refusing stale, incomplete, or mismatched generations before touching disk.
- Includes only allowlisted fields: versioned identity, human-readable manifest path, Box workspace and worktree paths, observed repository facts, workspace service readiness, optional ready loopback routes and ports, declared `argv` commands, policy facts, and the v0.1 accepted-loss durability statement.
- Excludes source repository paths, private Git stores, runtime metadata, environment variables, credential locations, Docker sockets, and unrelated Machine paths, failing closed if any registered sensitive value appears in the encoded payload.
- Canonicalizes collection ordering and persists `context.json` at mode `0600` through `internal/atomicfile`.

## Constraints

- Support claims require real execution evidence on the claimed platform.
- Failed invariant checks, secret-canary hits, or symlinked destinations leave any prior `context.json` untouched.

## Verified acceptance criteria

- The writer produces a document matching supplied live observations and refuses any incomplete or stale generation.
- Schema validation and golden files cover stable field names and additive route/port compatibility.
- Secret canaries and unrelated host paths are excluded from both persisted documents and returned errors.

## Implementation details

- `internal/contextdoc` validates Box identity, generation number, Plan digest, `READY` state, complete repository facts, workspace-service readiness, and optional route/port readiness as strict preconditions before replacing any file.
- Encoding uses an explicit allowlist rather than redacting a raw runtime dump, then scans the serialized bytes against caller-registered sensitive values and fails closed without echoing the sensitive value in error messages.
- Output is canonically sorted, formatted as deterministic indented JSON with a trailing newline, and persisted via `internal/atomicfile` at mode `0600`.
- Checked-in golden fixtures validate byte-for-byte writer output and both empty-endpoint (Milestone 1) and populated route/port payloads against `schemas/v1alpha1/context.schema.json`.
